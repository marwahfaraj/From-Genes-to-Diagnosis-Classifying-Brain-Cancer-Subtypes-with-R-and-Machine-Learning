# From-Genes-to-Diagnosis-Classifying-Brain-Cancer-Subtypes-with-R-and-Machine-Learning

This project leverages gene expression data from the CuMiDa database (GSE50161) to build and evaluate machine learning models for classifying brain cancer subtypes. The workflow covers data cleaning, exploratory analysis, dimensionality reduction, model training and comparison, and deployment via a user-friendly Shiny web app.

## 🧬 Project Overview & Pipeline

### 1. Data Cleaning & Preprocessing
- Remove duplicates, constant columns, and rows/columns with excessive missing values.
- Impute missing numeric values with the median.
- Normalize numeric features.
- Save the cleaned dataset for downstream analysis.

### 2. Exploratory Data Analysis (EDA)
- Visualize class distribution, gene variance, and sample-level summaries.
- Generate heatmaps for sample clustering and gene correlation.
- Identify the most variable genes for further analysis.

### 3. Dimensionality Reduction
- **PCA**: Reduce dimensionality to 20 principal components, explaining ~69.5% of variance.
- **t-SNE**: Visualize sample separability in 2D space.
- Save PCA scores and t-SNE coordinates for modeling and visualization.

### 4. Modeling & Evaluation
- Compare multiple models: Random Forest (RF), XGBoost (XGB), SVM, Naive Bayes (NB), Neural Net (NN).
- **Nested Cross-Validation**: To ensure a robust and unbiased evaluation, a nested cross-validation strategy was employed.
    - The **outer loop** splits the data into training and testing folds to provide a final, unbiased estimate of model performance on unseen data.
    - The **inner loop** performs hyperparameter tuning (e.g., finding the best `mtry` for Random Forest) on the training portion of each outer fold.
- Handle class imbalance using two strategies within the CV process: Weighted and SMOTE.
- Evaluate models on Accuracy, Kappa, F1, and other metrics.
- Select the best overall model (XGBoost) for the final deployment.

### 5. Final Model Training & Deployment
- The best model (XGBoost) is retrained on the *entire* training dataset.
- This final model is then evaluated one last time against a completely held-out test set that was separated before the nested cross-validation process began.
- The final trained model, test set, and performance metrics are saved for use in the Shiny application.

## 🌐 Shiny App: Brain Tumor Classification Tool

A user-friendly Shiny web app is provided for interactive predictions and result exploration.

**Features:**
- Upload a CSV file with 20 PCA features (PC1-PC20) for new samples
- Get predicted brain tumor subtype and confidence score
- View model performance metrics (accuracy, precision, recall)
- Explore confusion matrix, feature importance, and prediction distribution
- Review detailed prediction results in a table

**How to Run:**
1. Ensure the final model (`shiny_app/model/final_model.rds`) and a test set (`shiny_app/data/test_set.csv`) exist (generated by the pipeline)
2. In R, run:
   ```r
   Rscript run_shiny_app.R
   ```
3. Open the app in your browser at `http://localhost:3838`.

**App Structure:**
- `app.R`: Main UI and server logic
- `run_shiny_app.R`: **(Recommended launcher)** Installs dependencies and runs the app.
- `www/`: Custom styles and images
